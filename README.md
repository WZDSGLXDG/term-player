# 终端音乐播放器（term-player）

零 npm 依赖的终端 TUI 播放器，Windows 本地可用。播放引擎默认 **mpv**（命名管道 JSON IPC，暂停 / seek / 音量 / 倍速全实时），
没有 mpv 时回退到 `ffplay`；元数据走 `ffprobe`，歌词读本地 `.lrc`。

## 功能

- **歌词**：本地 `.lrc`，逐行高亮 + 自动居中滚动，支持 `[offset:]`、GBK 编码回退、跨目录模糊匹配
- **播放控制**：空格暂停/继续、`←→` 快退快进 5 秒、`<>` 倍速、`+-` 音量 —— mpv 后端下全部实时生效
- **曲库**：递归扫描、按文件夹自动分类、`/` 实时搜索
- **播放模式**：列表循环 / 单曲循环 / 随机洗牌（洗牌不重复自己）
- **记忆**：上次听到哪首、第几秒、音量、倍速、视图，下次打开**停在暂停状态**等你按空格
- **实时监视**：曲库增删歌曲自动刷新，歌词文件改动自动重载
- **两种视图**：`l` 在歌词视图与列表视图间切换；列表视图左右两栏，右侧同步显示当前歌词
- **零依赖**：只用 Node 内置模块，不需要 `npm install`

**不需要构建**：没有任何编译步骤，装好 Node.js 直接 `node player.js`。

## 依赖

| 需要                          | 说明                                                                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Node.js ≥ 16                | 只用内置模块，**不需要 npm install**                                                                                                                      |
| `ffmpeg` / `ffprobe`        | 已在 `C:\ffmpeg\bin` 或 PATH 里（元数据与 ffplay 后端） |
| `mpv.exe`（推荐）或 `mpvnet.exe` | 自动探测 PATH、`D:\software\mpv`、`C:\Program Files\mpv`、`D:\software\mpv.net`；**纯 mpv 优先**（无窗口、启动 177ms），mpv.net 作回退（426ms、需要藏窗口）。两者暂停/seek/音量/倍速全实时 |

## 第一次使用

1. 装 **Node.js ≥ 16**，再装 **mpv**（推荐，或在 `--mpv` 里给路径）与 **ffmpeg**（含 `ffprobe`）。都在 PATH 上就会被自动找到。
2. 解压后在本目录跑一次，把曲库记进 `config.json`：

   ```powershell
   node player.js "<你的音乐目录>" --set-dir "<你的音乐目录>"
   ```

   之后双击 `play.cmd`、或者直接 `node player.js` 就能放。
3. 想随时在终端敲 `tp` 启动：跑一次 `install-tp.cmd`（只写 `%USERPROFILE%\.local\bin\tp.cmd`，不改 PATH、不写注册表）。

打包分发给别人时**不要带 `config.json` 和 `meta-cache.json`**：前者是你的曲库路径与播放进度，后者是本机 ffprobe 缓存。

## 用法

```powershell
cd <解压出来的目录>\term-player

$Music = "<你的音乐目录>"     # ← 换成你自己的曲库目录（下面所有命令都用这个变量）
node player.js "$Music"                                              # 递归扫描并播放
node player.js "$Music" --lyrics "<歌词目录>" --lyrics "<另一个歌词目录>"   # 歌词在别的文件夹
node player.js "$Music" --no-recursive --volume 60                    # 只看当前层，音量 60
node player.js "$Music" --start 90                                    # 从第 90 秒开始
node player.js "$Music" --selftest                                    # 非交互自检
node player.js "$Music" --rendertest                                  # 打印一帧并检查排版
$env:TP_COLS=80; node player.js "$Music" --rendertest                 # 模拟 80x24 终端再看一遍排版
node player.js "$Music" --mode shuffle                                # 播放模式：all/one/shuffle
node test/run-tests.js                                                # 177 项单元测试
node player.js "$Music" --backend mpv --mpv "<mpv.exe 路径>"           # 指定播放器
node player.js "$Music" --backend ffplay                              # 强制回退到 ffplay
node player.js "$Music" --lyrics-lines 8                              # 歌词固定 8 行
node player.js --set-dir "$Music"                                     # 记住默认目录（以后不用再输）
node player.js                                                        # 直接用默认目录启动
node player.js --show-config                                          # 看当前保存的配置
node player.js --help                                                 # 全部参数和按键说明
```

也可以双击 `play.cmd`，或 `play.cmd "<你的音乐目录>"`。

**默认音乐目录随时能改，不用重装、不用改代码**，三条路任选：

- `node player.js --set-dir "<新目录>"` —— 改一次就记住，之后 `node player.js` / 双击 `play.cmd` 都从那儿起；
- 直接编辑 `config.json` 的 `musicDir`（这一个字段就是「默认曲库」，文件里别的键不影响）；
- 临时换个库：`node player.js "<另一个库目录>"`，只对这次运行生效，不覆盖默认值。

## 打包分发

```powershell
.\pack-release.ps1          # → dist\term-player-<日期>.zip
```

只装 `player.js` / `lib\` / `test\` / `play.cmd` / `install-tp.cmd` / `README.md`，
**自动剔除 `config.json`（你的曲库路径与播放进度）和 `meta-cache.json`（本机 ffprobe 缓存）**。
对方装好 Node + mpv（或 ffmpeg）后解压即可用，整包约 **57 KB**。

**依赖只有两样**，都不用装 npm 包：Node.js ≥ 16，和 mpv（推荐）或 ffmpeg（含 ffprobe、ffplay）。
没装 mpv 也能用，只是没有实时倍速、暂停会多 0.1–0.3 秒静音间隙（见「已知限制」）。

## 按键

| 键 | 作用 |
|---|---|
| `空格` | 播放 / 暂停（还没开始播时，先从选中这首开始） |
| `←` `→` | 快退 / 快进 5 秒 |
| `↑` `↓` 或 `j` `k` | 列表里移动选中 |
| `Enter` | 播放选中项 |
| `n` / `p` | 下一首 / 上一首（按当前播放模式走） |
| `m` / `M` | 切换播放模式：循环 → 单曲 → 随机（`M` 反向） |
| `l` 或 `Esc` | 歌词视图 ⇄ 列表视图 |
| `+` / `-` | 音量 ±5（mpv 后端实时生效） |
| `<` / `>`（或 `,` `.`） | 倍速：0.5 → 0.75 → 1 → 1.25 → 1.5 → 2（**需要 mpv 后端**） |
| `/` | 搜索：**底部提示条变成输入框**（固定 30 列、光标 `▏`、右侧实时匹配数量），边打边过滤；Enter 确认后提示条最前面仍显示「搜索「关键字」 N 首」，Esc 取消 |
| `g` / `G` | 跳到列表首 / 尾 |
| `PgUp` / `PgDn` | 列表翻页 |
 | `[` / `]` | 切换分类（文件夹） |
 | `q` 或 `Ctrl+C` | 退出 |

## 分类（按文件夹）

曲库按**音乐目录下的第一层文件夹**自动分类，顶部第二行就是分类导航条：

```
  全部 240   ·   流行 96   ·   摇滚 58   ·   民谣 44   ·   纯音乐 42
```

`[` / `]` 在「全部」和各分类之间循环切换，切过去列表和播放范围都只剩该分类的曲目，
当前分类反显；正在播放的歌在信息区带 `[分类]` 标签。

分类由扫描结果实时算出，文件夹增删后导航条跟着变；当前分类被删光时自动退回「全部」。

## 播放模式

按 `m` 在三种模式之间循环（`M` 反向），当前模式显示在底部提示条第 2 项（`m 循环` / `m 单曲` / `m 随机`）。

| 模式 | 一首播完之后 | 手动 `n` |
|---|---|---|
| `循环`（默认） | 回到第一首继续（**范围＝当前列表**：选了某个文件夹就只在这个文件夹里转） | 在最后一首按下会绕回第一首 |
| `单曲` | 重播这一首 | 仍然切到下一首（只有"播完"才重复） |
| `随机` | 从牌堆抽下一首 | 也抽牌堆（往后倒不是上一首，是另一首随机） |

**随机是"洗牌不重复"**，不是每次随机抽一首：

1. 把当前视图（受分类/搜索过滤后）的下标洗一遍，当前这首压到牌堆最底，保证不会立刻重播自己；
2. 每播完一首从牌堆弹一张出来，牌堆空了再重洗 —— 所以一轮之内**不会重复**，158 首就是 158 首不重样；
3. 切分类、搜索、曲库增删都会把牌堆作废重洗（下标已经对不上了）。

模式会记进 `config.json` 的 `playMode`，下次启动沿用；临时改可以用命令行覆盖：

```powershell
node player.js "<你的音乐目录>" --mode shuffle     # 循环 all / 单曲 one / 随机 shuffle
```

## 记住上次听到哪

每次启动会**回到上次那首歌、那个位置**，并沿用上次的音量、倍速、播放模式和视图（歌词 / 列表）。
启动后是**暂停状态**：歌已经载入、停在那个位置，但不会自己出声，**按空格（或 Enter 重播当前）才开始放**。
这样半夜打开不会突然轰一声。顶部会提示一行「上次停在 02:15，从这里接着放」。

这些都存在 `config.json`：

| 键 | 含义 |
|---|---|
| `musicDir` | 默认音乐目录（`--set-dir` 改） |
| `playMode` | `all` / `one` / `shuffle`（旧版本存的 `seq` 会被忽略，自动按 `all` 跑） |
| `volume` / `speed` | 音量、倍速 |
| `viewMode` | `lyrics` / `list` |
| `last` | `{ path, position, at }`：上次那首、听到第几秒、什么时候存的 |

- **写盘时机**：播放中最多每 **10 秒**一次；切歌前、按 `q` 退出时**立刻**写一次——正常退出和崩溃都不会丢。
- **容错**：开头 3 秒内、结尾 5 秒内都记成 `0`（下次从头听）；歌被删/改名了 → 回到第一首，不报错。
- **优先级**：`--start 90` 高于上次进度；`--volume` 高于配置里的音量。
- **忘掉进度**：

```powershell
node player.js --forget        # 只清 last，别的配置不动
```

## 歌词匹配规则

歌词可以在**任意文件夹**，用 `--lyrics` 传，可以传多次。不给的话自动找这些位置：

- 音乐目录本身
- 音乐目录下的 `lyrics` / `Lyrics` / `歌词` / `歌詞` / `lrc`
- 音乐目录**同级**的上述目录

匹配按这个优先级打分，取最高分：

| 分数 | 条件 |
|---|---|
| 100 | 文件名完全一致 |
| 90 | 归一化后一致（去编号 `01.`、去括号内容、去标点空格、忽略大小写）；也包括「只要歌名」对上了：`Song Title-Artist One.mp3` → `Song Title - Artist One & Artist Two-album.lrc` |
| 80 | 命中 LRC 里的 `[ti:标题]` 标签 |
| 40–60 | 互相包含且长度比例 ≥ 0.6 |
| < 40 | 视为不匹配，界面显示"没有匹配到歌词" |

命名规则上做了兼容：`歌名 - 歌手 - 专辑` 会在 `-` / `–` / `—` 处切开（**有没有空格都切**），
同时生成"完整名 / 只要歌名 / 歌名+歌手"三个键去比对，所以歌曲和歌词两边的后缀不一致也能对上。

所以 `01. 测试歌曲一.mp3` 能匹配 `测试歌曲一.lrc`，`测试歌曲二 (Live).flac` 能匹配 `测试歌曲二.lrc`。

支持的特性：

- `[mm:ss.xx]` / `[mm:ss:xx]` / `[mm:ss]` 三种时间格式，一行多个时间戳
- `[offset:+500]` 标签（毫秒，正值表示歌词提前）
- **编码自动识别**：UTF-8（含 BOM）/ UTF-16 / GB18030 都能读，老 GBK 歌词不会乱码
- 只有带时间轴的 `.txt` 才算歌词，纯文本会被跳过

## 文件夹实时更新

用 `fs.watch` 递归监视音乐目录和歌词目录，改动后 400ms 去抖重新扫描：

- 新增歌曲 → 列表立刻多出来
- 删除文件 → 从列表消失；如果删的正是当前播放的，停止播放并提示
- 修改歌词文件 → 重新索引，当前歌没匹配到的话会补匹配

## 界面：进度条与歌词
**进度条**用实心块铺满：

```
 ████████████████████▒─────────────────────────────────── 01:23 / 04:26 ▶  31% 1x  vol 80
```

- 已播部分是实心 `█`（青绿），未播是暗色 `─`，边界那个字符每 350ms 在 `█▓▒` 之间脉动
- 右侧跟已播百分比、播放状态图标（▶ 播放 / ‖ 暂停 / ■ 停止）、**倍速（始终显示，默认 `1x`）**和当前音量
- 宽度不够时自动降档：先去掉 `vol 80`，再只留状态图标和倍速；进度条最短保留 4 格，40 列也不超宽
- 总宽度严格等于分配宽度，不随进度抖动

**歌词高亮**：只高亮**当前正在唱的那一句**（亮青色 195 + 加粗），上下的句子统一暗灰——
不提前高亮下一句，也不做逐字填充。翻页时整块歌词以当前句为中心滚动。

**列表视图是双栏的**（终端宽度 ≥ 80 列时）：左侧是曲目列表（可滚动、当前曲带 ▶、回车播放），
右侧同步显示**正在播放那首歌的歌词**，跟着播放进度滚动。窄屏（<80 列）自动退回单栏。
**展开列表不会遮掉进度条**：列表上方始终保留「当前曲目 · 歌手」和进度条两行，跟歌词视图一致。

**列表每行的信息量**：只有「标记 序号 名称」，时长钉在右侧最外 7 列（`DUR_W`）**右对齐**——
它的起点只由列表宽度决定，不随名称长短或歌手长度浮动，所以时间永远在同一条竖线上（`--:--` 与 `03:18` 尾部对齐）。
**歌手只显示在正在播放那一行**（最多 12 列，和名称抢空间时名称优先），其余行只有名称，一屏能多看几首。
顶部「当前曲目 · 歌手 + 进度条」两行仍然完整，正在播的那首在两处都能看到完整信息：

>     25  示例歌曲一                                --:--      ← 只有名称 + 对齐的时长
>  ▶  36  示例歌曲二                       某歌手   04:08      ← 播放行额外带歌手，时长位置不变
>     37  示例歌曲三                                --:--

**刚放进来的新歌也守同一条规则**：`songLabel()` 还没拿到 `meta.title` 时，用文件名清洗后的歌名 ——
去掉前导编号 `01.` 和「- 歌手-专辑」后缀（切分规则和歌词匹配的 `keysOf` 一致：`-` / `–` / `—` 都算分隔，
有没有空格都切）。所以新导入的歌不会把「新导入的歌名 - 某歌手 - 某专辑」整串甩进列表；
列表滚到它、0.5 秒探测完成后自动换成文件里的 `title`。

**底部操作提示条**贴在终端**最后一行**（下面不再留空行），整行铺深灰底（`48;5;236`）做成状态条：
按键名亮青加粗（`38;5;117` + bold），说明文字浅灰（`38;5;250`），一眼能和歌词正文区分开。
窄屏放不下时按**优先级**截断（顺序：空格 → m → ↑↓ → np → <> → ←→ → q → l → [] → +- → /），
第 2 项 `m 循环` 会随按键变成 `m 单曲` / `m 随机`，既是快捷键提示也是当前模式显示。
所以 80 列下仍然能看到 `q 退出`；再用 `-1` 列余量，避免贴底行写满整行时在部分终端触发换行滚动。

**刷新率与流畅度**：主循环 **20fps（50ms）**，并用**差分重绘**——只把和上一帧不同的行写到终端
（`ESC[n;1H` 定位 + 清行尾），不是整屏重画。实测：

| 场景 | 每帧写入 | 重绘行 |
|---|---|---|
| 首帧 | 2760 字节 | 全部 |
| 进度推进（前进 2 秒） | ~510 字节 | 4 行（进度条 + 3 行歌词） |
| 跳到另一个歌词段 | ~1870 字节 | 15 行 |
| 画面上什么都没变 | 0 字节 | 无 |

### 歌词区大小

歌词区默认占**可用高度的 70%**（最少 3 行、最多 14 行），上下留白均分，跟着终端大小自动变。想固定行数：

```powershell
node player.js "<你的音乐目录>" --lyrics-lines 8     # 固定 8 行
```

终端字体的**字号**是终端自己的设置，程序改不了——想再大就调终端字号（Windows Terminal 里 `Ctrl+加号`），
程序会自动重新排布行列。

## 资源占用

三处独立开销，都实测过（158 首的库）：

| 场景 | 优化前 | 现在 | 做法 |
|---|---|---|---|
| **启动扫元数据** | 158 个 ffprobe / **1360 ms** / CPU 1047 ms | 首次 40 个 / **262 ms** / CPU 188 ms；之后 **0 个 / 5 ms** | 只探「当前播放 + 可见窗口」；ffprobe 结果落盘，用 `size + mtime` 校验新鲜度 |
| **空闲帧**（暂停、画面不动） | 20fps 一直重算整帧 | **直接跳过渲染**，实测 0.00% CPU | tick 里判断「有变化 / 正在播放 / 消息未过期」才重算 |
| **播放中帧** | 0.24 ms/帧 | 0.24 ms/帧（本来就够快） | 差分重绘，20fps 折合 **0.3–0.5% CPU** |

内存 **RSS 45–54 MB**（复测峰值 47 MB）/ heapUsed 7–8 MB，大头是 Node 自己的运行时；曲库 158 首 + 37 个歌词索引的对象不到 1 MB。
mpv 是独立进程，另有 30–40 MB，暂停时它不占 CPU。

`meta-cache.json`（158 首实测 **≈ 54 KB**）就是那份元数据缓存，结构是 `{ v: 1, files: { 路径 → { size, mtimeMs, meta } } }`：
**删掉不影响使用**，只是下次要把看过的再探一遍；音频文件被改了（重新转码、换码率）会因为 `size/mtime` 变化自动重探。

> 注：Windows 的 `process.cpuUsage` 精度是 15.6 ms 一个刻度，所以百分比只到 ±0.2% 的量级，别把小数点后两位当真。

## 播放后端

程序会自动挑后端，也可以在命令行指定：

| 后端 | 怎么用 | 能力 |
|---|---|---|
| **mpv.exe**（首选） | 自动探测，或 `--mpv <路径>` | 实时暂停/seek/音量/倍速；无窗口；启动到能播 **177 ms** |
| mpv.net（同样支持，本机已卸载） | 同上 | 能力相同（同一个 libmpv），但启动 **426 ms**、自带 GUI 窗口需要 `ShowWindow` 藏掉 |
| `ffplay`（回退） | `--backend ffplay` | 能放，但每次暂停/seek/调音量都要重启进程（167ms 空档），不支持倍速 |

mpv 后端走 `--input-ipc-server` 命名管道发 JSON 命令，实测（mpv.net v7.1.2 / mpv v0.41）：

| 操作 | 结果 |
|---|---|
| 暂停 | success，0.8s 内位置漂移 **0.000s**，**不重启进程** |
| seek | 精确到目标值（109s → 110.15s，含正常播放推进） |
| 倍速 2x | success，1 秒墙钟位置前进 **1.74s**（含插值误差） |
| 音量 | 实时改，读回一致 |

### 为什么不是 WMP / WinRT

最早试过系统自带的两条路，都不行：

| 后端 | 结果 |
|---|---|
| WMP COM (`WMPlayer.OCX`) | 三种格式全部卡在 `playState=9`(Transitioning)，`currentPosition` 恒为 0 |
| WinRT `Windows.Media.Playback.MediaPlayer` | `PlaybackState=None`，`Position` 恒为 0 |
| **`ffplay` 进程** | ✅ 可用（作为回退） |
| **mpv / mpv.net IPC** | ✅ 最佳 |

### ffplay 回退时的行为

没装 mpv 时用 ffplay：位置靠本地时钟推算，暂停/seek 一律"记位置 + 杀进程 + 从新位置重启"，
进度条准（±0.3s）、暂停准（0.000s 漂移），但每次操作有 167ms 静音间隙，且没有倍速。

实际体验：

- 进度条、时间显示准确（±0.3s，来自 `--selftest` 实测：从 5s 起播 1.5s 后显示 6.39s）
- 暂停位置精确（实测 0.8s 内漂移 **0.000s**）
- seek 到指定位置准确（实测目标 18.0s，1.2s 后显示 19.09s，即正常推进）
- **代价**：每次暂停/恢复/seek/调音量有静音间隙，因为进程要重启

关于这个间隙，做了两件事，也测了它的下限：

1. **连按合并**：seek 之间 180ms、音量之间 220ms 内的连续操作只真正重启一次。
   以前按住 `+` 调音量会一次堆一个进程、卡成幻灯片，现在整串只重启一次。
2. **缩短探测**：加 `-probesize/-analyzeduration`，但对本地文件收益很小。

实测 ffplay 的启动开销是 **167ms**（播 1 秒片段的墙钟 1167ms），这是"重启式 seek"的物理下限，
代码层面压不下去。要彻底消除，只有换 MCI 那条路（见「已知限制」最后一条）。

## 移动文件夹 / 换机器

**整个 `term-player` 文件夹可以随意移动、改名，甚至换盘符**——代码里所有内部路径都用 `__dirname` 定位
（`config.json`、`lib/hide-window.ps1`），写死的绝对路径只出现在 mpv 的**搜索候选**里（`D:\software\mpv`、
`C:\Program Files\mpv` 等），找不到就退回 PATH 上找，不影响搬动。

搬完只需要重绑一次终端命令（1 秒）：

```powershell
cd <新位置>\term-player
.\install-tp.cmd        # 重写 %USERPROFILE%\.local\bin\tp.cmd，指向新位置
tp                      # 新终端里直接可用
```

实测过三种情况：搬到别的盘、搬到**带空格**的
`...\my folder\term player`、以及搬回原处——每次 `tp` 都跟着打印新位置的配置（用一个 `marker` 字段验证），
搬完不重绑则 `tp` 会报找不到 `player.js`，重绑即恢复。

`config.json` 跟着文件夹走，所以**默认音乐目录和播放模式不会丢**；键表见「记住上次听到哪」
（`musicDir` / `playMode` / `volume` / `speed` / `viewMode` / `last`）。
不想要 `tp` 这个命令，删掉 `%USERPROFILE%\.local\bin\tp.cmd` 即可（不改 PATH、不写注册表）。

**换机器要额外准备**：`mpv.exe`（或用 `--mpv` 指定路径 / 用 ffplay 回退）和 `ffprobe`（PATH 上或 `C:\ffmpeg\bin`）。

## 已知限制

- **歌词覆盖率取决于你放了多少 lrc**：在一个 158 首歌、37 个歌词文件的库上实测，命中 39 首
  （37 个精确 + 2 个归一化），其余 119 首是库里确实没有对应歌词，不是匹配失败。
  想看自己库上的情况：`node test/match-report.js "<你的音乐目录>"`

- 需要真实交互终端（Windows Terminal / conhost 均可）；管道或重定向下会拒绝启动，请用 `--selftest`
- 终端必须支持 ANSI 转义（Windows 10+ 默认支持）
- 歌词按**文件名/标题**匹配，不做音频指纹；同名歌曲会命中第一条
- 播放列表是当前目录树的快照，不支持手动排序或拖拽
- 元数据是**按需探**的：列表里还没滚动到的曲目时长显示 `--:--`，滚到附近 0.5 秒内补齐（第一次运行如此；之后走缓存，几乎瞬时就有了）
- `ffplay` 音量只能重启进程生效，调音量会有一次短暂静音
- **没接 Windows MCI**：实测 `mciSendString` 对 mp3 的 open/play/pause/seek 全部可用、位置精确到毫秒、
  暂停零漂移，理论上能给 mp3 做到无间隙暂停/seek；但（1）只覆盖 mp3/wav，本库 72 首 flac 用不了，
  （2）`open` 返回 0 不等于能出声（flac 就是 rc=0 但静音），（3）Node 调 `winmm.dll` 需要 FFI，
  得再挂一个常驻 PowerShell 代理进程。权衡后没做——`ffplay` 方案只多 0.1–0.3s 间隙，功能是完整的。

- **多声道文件会降混成立体声**：mpv 启动参数里带了 `--audio-channels=stereo`。
  原因不是偏好，是必须——库里有 `12 声道 / channel_layout=unknown` 的 ogg，
  mpv 的 WASAPI 输出遇到这种布局会**直接崩溃**（`0xC0000005` 访问违例，`--audio-channels=auto-safe` 也拦不住）。
  实测强制 stereo 后：9 个 ogg 全部可播，mp3/flac/m4a 不受影响。

- **倍速只有 mpv 后端支持**：`ffplay` 没有运行时变速能力（`-af atempo` 只能启动时指定，改了要重启进程），
  用 ffplay 时按 `<` / `>` 会提示"当前后端不支持倍速"。装了 mpv / mpv.net 就自动有了。
- **mpv.net 的窗口会被自动藏起来**：它是 GUI 程序，`--no-video --force-window=no` 只关视频、不关它自己的主窗口，
  所以启动后会调用 `lib/hide-window.ps1` 用 `ShowWindow(SW_HIDE)` 把它藏掉，切歌后也会再藏一次。
  实测：进程有 10 个顶层窗口，**可见 0 个**，音频照常（位置持续前进）。mpv.exe 本身无窗口，这个调用对它无害。
